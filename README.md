# AI Crypto Advisor

A personalized crypto investor dashboard. The app learns about the user through a short onboarding quiz, then shows a daily dashboard tailored to their interests: market news, coin prices, an AI-generated insight and a fun meme. Every section has 👍/👎 voting, and votes are stored with context for future recommendation improvements.

Built as a take-home assignment for Moveo.

## Features

- **Sign up / log in** with email, name and password. Passwords are hashed with bcrypt, sessions use JWT (7 days).
- **Onboarding quiz** (3 steps): crypto assets of interest, investor type (HODLer, Day Trader, NFT Collector) and preferred content types. Saved to the database as user preferences.
- **Personalized daily dashboard.** The sections shown follow the content types selected in onboarding:
  - **Market News** (when "Market News" is selected): CryptoPanic API with a static fallback.
  - **Coin Prices** (when "Charts" is selected): CoinGecko API, for the assets the user picked, with 24h change.
  - **Fun Crypto Meme** (when "Fun" is selected): a fresh meme on every refresh.
  - **AI Insight of the Day**: always shown. It is generated by a free LLM on OpenRouter, personalized by investor type and assets, and generated once per user per day.
- **Voting** (👍/👎) on every section and on each news item. Clicking the active vote again removes it.
- **Protected routes**: unauthenticated users are redirected to login; users without preferences are redirected to onboarding.
- **Resilient by design**: each dashboard section is loaded independently, so one failing external API never breaks the whole page.

## API overview

All routes except `/api/auth/*` and `/api/health` require `Authorization: Bearer <token>`.

| Method | Route | Description |
|---|---|---|
| GET | `/api/health` | Health check |
| POST | `/api/auth/signup` | Register (`email`, `name`, `password`) |
| POST | `/api/auth/login` | Log in, returns JWT |
| GET | `/api/me` | Current user |
| GET / POST | `/api/preferences` | Read / save onboarding answers |
| GET | `/api/dashboard` | News, prices, insight and meme for the user |
| GET | `/api/votes` | The user's votes |
| POST | `/api/votes` | Create or change a vote (`section`, `itemId`, `value` = 1 or -1) |
| DELETE | `/api/votes` | Remove a vote (`section`, `itemId`) |

## Database schema

```
User         id, email (unique), name, passwordHash, createdAt
Preference   id, userId (unique), assets[], investorType, contentTypes[]
Vote         id, userId, section, itemId, value (+1 / -1), metadata (JSON), createdAt
             unique (userId, section, itemId)
DailyInsight id, userId, date, text          unique (userId, date)
```

## Running locally

**Prerequisites:** Node.js 20+ and a PostgreSQL database (a free [Neon](https://neon.tech) project works well).

### 1. Backend

```bash
cd server
npm install
cp .env.example .env        # then fill in the values
npx prisma migrate deploy   # create the tables
npx prisma generate         # generate the Prisma client
npm run dev                 # http://localhost:4000
```

### 2. Frontend

```bash
cd client
npm install
cp .env.example .env        # VITE_API_URL=http://localhost:4000/api
npm run dev                 # http://localhost:5173
```

## Design decisions and trade-offs

- **CryptoPanic is now a paid API.** The free tier no longer exists, so the news service supports a key through `CRYPTOPANIC_KEY` but falls back to a static JSON file (`server/src/data/news.fallback.json`) when no key is set or the API fails. The assignment explicitly allows this fallback.
- **Memes.** Reddit blocks server-side requests (HTTP 403 / HTML challenge pages), so memes come from the public `meme-api.com` (r/cryptocurrencymemes), with NSFW and non-image posts filtered out. If it is unavailable, a random meme from a static JSON file is shown. A new meme is picked on every refresh.
- **AI insight.** Uses OpenRouter's free models. The prompt is built from the user's investor type and assets, and asks for general, non-advisory content. The result is stored per user per day in `DailyInsight`, so each user triggers at most one LLM call per day, which keeps the app within free-tier rate limits. Truncated or failed responses fall back to a prepared text for the investor type.
- **Caching.** Prices are cached in memory for 1 minute and news for 5 minutes to respect free API rate limits. On a CoinGecko failure the last cached value is served when available.
- **Partial failures.** The dashboard endpoint uses `Promise.allSettled`; a failing section is returned as `null`, shown as "temporarily unavailable", and logged on the server.
- **Votes are idempotent.** A vote is unique per `(user, section, item)` and is upserted, so repeated clicks change the vote instead of creating duplicates.
- **Optimistic UI.** Votes update instantly in the interface and roll back if the request fails.
- **Prices.** CoinGecko is the data source. An optional free Demo API key (`COINGECKO_API_KEY`) avoids rate limits (HTTP 429) that happen on the shared IPs of free hosting. Prices are cached for one minute, and the last cached values are served if a request fails. Prices are only requested for users who selected "Charts".
- **Personalization.** - **Personalization.** Sections are returned only for the content types the user chose, so unselected sections are not fetched at all, which also saves free-tier API quota. The "Social" option adds a focus on community sentiment and social media trends to the AI insight, since there is no dedicated social section.

## How feedback can be used to train and improve recommendations (bonus)

This part is a proposal; it is not implemented.

### What is stored today

Every vote is saved as a row in `Vote`:

| Field | Purpose |
|---|---|
| `userId` | who voted |
| `section` | `news`, `prices`, `insight` or `meme` |
| `itemId` | the exact item (news id, insight date, meme id) |
| `value` | +1 or -1 |
| `metadata` | context at vote time (investor type, assets, content types), built on the server from the user’s saved preferences, never taken from the client |
| `createdAt` | when the vote was first cast |
| `updatedAt` | when the vote was last changed |

Combined with `Preference` (assets, investor type, content types) and `DailyInsight` (the generated text), this already forms a labeled dataset: *(user profile, content item, rating)*.

### Stage 1: rule-based re-ranking (no ML required)

- Aggregate scores per item and per user segment (for example, average vote of HODLers for each news source or topic).
- Boost sections and topics a user upvotes, hide sources they repeatedly downvote.
- Rank memes by net votes within the user's segment, so well-liked memes appear more often.
- Cheap, explainable, and works from the first votes.

### Stage 2: collaborative filtering and contextual bandits

- Build a user × item matrix from votes and apply matrix factorization or item-based collaborative filtering to recommend items liked by similar users (cold-start users fall back to their investor-type segment).
- Use a contextual bandit (for example Thompson sampling) with user context as features, to balance showing known favorites (exploitation) against trying new topics and sources (exploration). Votes are the reward signal.

### Stage 3: improving the LLM insight

- **Prompt personalization:** add the user's recent liked and disliked insights to the prompt as few-shot examples ("the user liked insights like..., avoid insights like...").
- **Preference dataset:** for each user/day, pairs of liked and disliked insights form (chosen, rejected) pairs that can be used for fine-tuning with preference optimization (DPO) or for training a reward model that re-ranks several generated candidates before showing one.
- **Evaluation:** track the like ratio per prompt version and model, and A/B test changes before rolling them out.

### Data pipeline and quality

- Periodically export votes to a feature table (profile features plus item features plus label) for offline training; keep a train/validation split by time.
- Account for position bias (items higher in the list get more votes) by logging position, and for noise by weighting users with enough votes.
- Respect privacy: use only pseudonymous ids for training, and delete a user's votes on account deletion.

## Known limitations

- Free-tier hosting: cold starts on the backend (30-50 s on the first request).
- Free LLMs on OpenRouter are rate limited and can be unavailable; the app then shows prepared fallback text.
- The static news fallback contains sample headlines, not live news, unless a CryptoPanic key is configured.
- No password reset or email verification (out of scope for the assignment).
- Price data depends on the CoinGecko free tier; if a request fails, the last cached prices are shown, or a "temporarily unavailable" message if there are none.
